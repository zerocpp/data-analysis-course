# Tasks 校验逻辑全链路（脚本.md）

> 适用版本：BigData v10.1.15　|　整理日期：2026-10-08
> 一句话：**一个 Task 从学生 workspace 到教师端入库分配，要连续通过 7 道独立校验；
> 每一道都有唯一的实现文件与稳定错误码，本地与服务器永远跑同一份规则。**

---

## 0. 总览：Task 的校验生命周期

```
学生 workspace（task.json / data.csv / agent.py / reference.py / .env）
  │
  ├─① validate_project          workspace 网关（run / export / build 三命令共用）
  │
  ├─② prepare_submission_staging  Build 专属：phase/student_id 合法 + Secret 排除
  │
  ├─③ validate_base_submission   Single-Package Base 层（学生端=服务器端，同一份）
  ├─④ package name ↔ manifest    包名一致性层
  ├─⑤ phase extension            P1 / P2 各自新增内容
  │
  ├─⑥ server receive + batch     身份外-内-Roster 交叉 + 跨包查重
  │
  ├─⑦ ingest → assignment 输入   OWNER/TASK/CATEGORY 一致性（12 个输入错误码）
  │
  └─（旁路）exposure 匿名视图     匿名 Task 的禁泄漏字段扫描
```

每一道失败都**立即终止**，绝不带病进入下一阶段。

---

## ① workspace 网关 —— `main/validation.py::validate_project`

Run / Export / Submission Build 进入前的唯一裁决；只做静态与可导入性检查，
不实例化运行对象、不执行任务。返回错误列表，非空即终止。

### 必需文件（validation.py:25）

```
.env  .env.example  agent.py  task.json  data.csv  reference.py
```

### 逐文件规则

| 文件 | 校验内容 | 位置 |
|---|---|---|
| `.env` | 必填键 `LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL`（只 parse，绝不写入 os.environ） | validation.py:30,205 |
| `task.json` | 合法 JSON **对象** | validation.py:212 |
| `task.json.expected_failure_mode` | ∈ 正式 14 类 FM（FM01–FM14）；**Internal Error 词汇**（timeout/token/memory/api/crash 等 36 个同义写法）一律显式拒绝——它们不是 Failure Mode | validation.py:124-165 |
| `task.json.hypothesized_failure_mode` | 字段可缺省（旧版兼容）；一旦出现必须 ∈ 14 类（含 FM10/FM13） | validation.py:168-189 |
| `data.csv` | 可被 pandas 读取；大小 ≤ 1 MB；行数 < 10000；列数 ≤ 100（上限来自 `policy/runtime_policy.json → task_data`） | validation.py:224-245 |
| `agent.py` | 可导入；存在可调用 `run`；签名**恰好** `(task, df, llm)`（多参/少参/预算参数都拒绝） | validation.py:247-261 |
| `reference.py` | 见下方独立 guardrail | validation.py:263-283 |

### reference.py guardrail（`check_reference_source`，validation.py:68-114）

标准答案脚本的强约束（教师 gold 的可信度基础）：

- 行数 < 200（policy `reference.max_source_lines`）；
- 语法必须合法（AST parse）；
- **只允许 import pandas / decimal**（纯内存计算，无 I/O、无系统访问）；
- 禁止 `open / exec / eval / compile / __import__` 调用；
- 禁止 pandas `read_*` 外部读取、禁止 `to_csv/to_pickle/to_json/to_excel/to_parquet/to_feather/to_sql` 写出；
- 可导入且存在 `reference(df)`，签名**恰好** `(df)`。

## ② Staging（Build 专属）—— `submission/staging.py`

`build_submission` 第一步，任何失败抛 `StagingError`（CLI 退出码 2），不产生部分树：

- `phase ∈ {phase1, phase2}`；`student_id` 匹配 `^[0-9A-Za-z_]{2,32}$`；
- 复跑 ① 的 `validate_project`（advisory 但尽早止损）；
- `task_id` 固化：已有保留；缺失自动生成 `T_<uuid4hex32>` 并写回；
- 组装 Contract 树时按 **Secret Guard** 排除（`.env` / `*.key` / `credentials` 等）；
  `.env.example` / `runs/` / 模板 docx 永不入包。

## ③④⑤ Single-Package 校验 —— 学生端与服务器端同一份实现

统一入口 `validate_single_package`（`submission/extension_validation.py:277`），
Build / Validate / Server Receive 三端复用；按层短路（Base FAIL 不跑扩展）。

### Base 层（`base_validation.py`，P1/P2 共用，错误码即稳定接口）

| 检查 | 失败码 |
|---|---|
| manifest.json 存在 / 合法 JSON 对象 | MISSING_MANIFEST / MALFORMED_JSON |
| manifest.schema_version 匹配 | BAD_MANIFEST |
| submission_phase ∈ {phase1, phase2} | INVALID_SUBMISSION_PHASE |
| student_id / task_id 存在且格式合法 | MISSING_/INVALID_STUDENT_ID、MISSING_/INVALID_TASK_ID |
| task/task.json 存在 / JSON / `hypothesized_failure_mode` ∈ 14 类 | MISSING_TASK_JSON / MALFORMED_JSON / INVALID_FM |
| task/data/ ≥ 1 个文件且单文件 ≤ policy 大小上限 | MISSING_TASK_DATA / DATA_TOO_LARGE |
| agent/agent_manifest.json + agent/agent.py 存在 | MISSING_AGENT_MANIFEST / MISSING_AGENT |
| **三处身份一致**（manifest / task.json / agent_manifest 的 student_id、task_id） | STUDENT_ID_MISMATCH / TASK_ID_MISMATCH |
| 预留服务器路径（validation/ registry/ canonical/ 等） | RESERVED_SERVER_PATH |
| 边界文件：.env / runtime_policy.json / runs/ / __pycache__/ / .git/ / *.pyc | FORBIDDEN_FILE |
| Secret Guard：文件名 fnmatch（.env/*.key/credentials/secret…）+ 内容扫描（`sk-…`、`LLM_API_KEY=`、PEM 头） | SECRET_FILE |
| `.env.example` 手工放入（legacy 兼容） | 仅 WARNING：DEV_TEMPLATE_FILE |

### Package Name 层（`extension_validation.py:153`）

- archive 文件名可解析：`<course>_P<phase>_<student_id>.zip`（`_v<digits>` 补交后缀合法）→ INVALID_ARCHIVE_NAME
- 文件名 phase / student ↔ manifest 一致 → SUBMISSION_PHASE_MISMATCH / STUDENT_ID_MISMATCH

### Phase Extension 层（只查该 Phase 新增内容）

**P1**（extension_validation.py:58）：`task_statement` 与 `hypothesized_failure_mode` 必填
→ MISSING_TASK_STATEMENT / MISSING_HYPOTHESIZED_FM

**P2**（extension_validation.py:94，v10.1.14 协议）：

| 检查 | 失败码 |
|---|---|
| assignment.json 存在 / JSON / anonymous_tasks 非空且不重复 | MISSING_ASSIGNMENT / INVALID_ASSIGNMENT |
| 实验报告.docx 存在 / 非 0 字节 / 可作为 docx 打开（zip + word/document.xml） | MISSING_EXPERIMENT_REPORT / INVALID_EXPERIMENT_REPORT |
| review-comments.json（唯一审稿记录）：顶层字典；key 集合 = 分配集合；**原始 JSON 重复 key 检出**；key=内层 task_id；字段恰 {task_id, score, comments}；score `type() is int` 且 1~5；comments 非空字符串 | MISSING_REVIEW_COMMENTS / REVIEW_COMMENTS_NOT_OBJECT / DUPLICATE_REVIEW_TASK_ID / MISSING/UNKNOWN_REVIEW_TASK / REVIEW_TASK_ID_MISMATCH / REVIEW_FIELD_MISSING/UNKNOWN / INVALID_REVIEW_SCORE / INVALID_REVIEW_COMMENTS / INVALID_STRUCTURE |

> Final Report（report/final_report.md）与旧 reviews/*.json 多文件协议已删除：
> 校验不再接受，Build 也不再打包。

## ⑥ 服务器端 receive + batch（UNTRUSTED，从零验证）

**receive**（`submission/receiver.py`）：Archive Intake 安全解压（拒绝 zip-slip / 绝对路径 /
symlink / 炸弹）→ **重跑 ③④⑤ 同一份 Validator** → 身份外-内-Roster 交叉
（UNKNOWN_STUDENT_ID；永不自动修复）→ raw 单文件 active 槽位（REJECTED 不占槽、
DUPLICATE_ARCHIVE 仅同 SHA、`--supersede` 显式替换、FROZEN 冻结）→ append-only 审计。
学生带入的 validation_status / registry / server_metadata 一律 IGNORE + REGENERATE。

**batch**（`submission/batch/validator.py`）：只对 Single-Package PASS candidate 做跨包检查——
`DUPLICATE_ACTIVE_STUDENT_ID`（同学生同 phase）、`DUPLICATE_TASK_ID`、`DUPLICATE_ARCHIVE`；
可解析包的重复进 diagnostics（不构成 reject）；产出 Excel/JSONL 报告。

---

## ⑦ Ingest → Assignment 输入校验（Task 的最后一关）

**ingest**（`submission/ingest.py`）：只有 Single+Batch 都 PASS 才入库；canonical Task/Agent
剥离一切身份字段；`archive_sha256` 幂等（重复 SKIP）；失败全量回滚。

**assignment 输入**（`assignment/input_builder.py` + `assignment/contract.py:55-67`，共 12 码）：

| 检查 | 错误码 |
|---|---|
| reviewer/task 学号重复 | ASSIGN_INPUT_DUPLICATE_REVIEWER / TASK |
| 每个 owner 恰有自己的 task（缺失/多出） | MISSING_OWN_TASK / COUNT_MISMATCH |
| owner 元数据存在且唯一 | OWNER_MISSING / OWNER_DUPLICATE |
| task 存在于 registry | TASK_NOT_EXISTS |
| 类别存在 / 合法（14 类 FM，**绝不猜补、绝不用 LLM 推断**） | MISSING_CATEGORY / INVALID_CATEGORY |
| metadata FM 与 task.json hypothesized FM 漂移 | CATEGORY_DRIFT |
| r 为正整数 | INVALID_R |
| owner 非 active 状态 | NOT_ACTIVE |
| phase 不匹配 | PHASE_MISMATCH |

## 旁路：Exposure 匿名 Task 校验（`exposure/contract.py`）

TA 分发的匿名 Task 包（恰好 10 个）另有独立红线：

- 数量**恰好** 10（`EXPOSURE_COUNT_ERROR`）；
- task.json 含嵌套结构递归扫描禁泄漏字段（student_id / author / gold / expected_answer /
  expected_failure_mode / reference_solution 等 15 个 key，大小写不敏感）→ `EXPOSURE_LEAK`；
- 包内禁 reference.py / .env / runtime_policy.json；
- Exposure 是学习材料：**不产生任何学生正式 Submission**。

---

## 错误码速查（学生最常遇到的）

| 阶段 | 高频错误码 | 典型原因 |
|---|---|---|
| ① 网关 | `workspace 缺少必需文件` / `task.json 不是合法 JSON` / `不是正式 Failure Mode` | 六件套不齐 / JSON 语法 / FM 写成 timeout 等 |
| ① 网关 | `data.csv 行数…超过上限` / `reference.py 拒绝：只允许 import pandas/decimal` | 数据超限 / gold 里写了 I/O |
| ③ Base | MISSING_TASK_JSON / DATA_TOO_LARGE / STUDENT_ID_MISMATCH | 手工改包 / 数据超大 / 包名学号与内容不符 |
| ③ Base | FORBIDDEN_FILE / SECRET_FILE | .env 或疑似密钥文件进包 |
| ⑤ P2 | MISSING_EXPERIMENT_REPORT / DUPLICATE_REVIEW_TASK_ID / INVALID_REVIEW_SCORE | 没另存实验报告 / review 重复 key / score 非法 |
| ⑥ batch | DUPLICATE_TASK_ID | 全班保留同一占位 task_id |
