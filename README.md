# DataChallenging



# DataChallenging是面向大模型时代《大数据分析技术》课程的本地教学系统

## 课程背景

传统数据分析课程通常采用“教师给数据、教师出题、学生完成分析”的形式。这样的训练能够帮助学生掌握基本的数据处理方法，但学生接触到的问题通常已经被教师定义清楚，很少需要自己判断一个问题是否完整、统计口径是否合理、结果是否能够验证，也很难系统观察大模型在陌生数据分析任务中的能力边界。

《大数据分析技术》课程采用两轮设计的方式组织实践。学生先设计自己的数据分析任务和数据分析智能体，再让自己的智能体处理其他同学设计的匿名任务，根据真实运行结果分析成功和失败原因，最后完成任务第二版和智能体第二版。

课程希望学生完成三方面训练：

- 能够把一个数据分析问题定义清楚，并给出可以重复验证的标准答案；
- 能够设计一个可以读取任务、处理数据、完成分析并检查结果的数据分析智能体；
- 能够根据真实运行结果判断智能体为什么失败，并据此修改任务和智能体。

课程最终形成“设计任务—构建智能体—运行陌生任务—分析失败—修改任务和智能体—统一评测”的完整过程。

## 系统功能简介

BigData 课程系统包含学生侧和助教侧，两侧通过课程提交包和匿名任务包交换课程产物。

包含学生端和助教端，两端数据相互独立，通过 `.tar.gz` 包交换课程产物。

系统包含学生端和助教端，两端数据相互独立，通过 `.tar.gz` 包交换课程产物。学生端主要支持学生完成从任务设计到最终提交的完整学习过程，包括编写数据分析任务、维护任务数据、编写并检查标准答案程序、编写数据分析智能体、在本地运行自己的任务和智能体、生成第一阶段提交包，并在提交前使用与助教端相同的规则完成本地验证。进入匿名任务阶段后，学生可以导入老师发放的匿名任务包，使用自己的智能体第一版运行 10 道陌生任务，查看运行结果和诊断信息，并据此完成 10 份评审意见。学生需要通过这些陌生任务观察智能体的成功与失败，分析失败发生在哪些环节，并把这些认识迁移到自己的设计中，进一步修改任务第一版形成任务第二版，修改智能体第一版形成智能体第二版，最后生成并验证第二阶段提交包。匿名任务分析本身不设置单独的提交节点，但对应的评审意见必须完成，因为这些记录既是学生分析陌生任务和智能体失败的过程依据，也是后续修改任务、修改智能体和撰写总结材料的重要基础。助教端主要负责批量接收和整理学生第一阶段提交，使用与学生本地验证一致的规则重新检查提交内容，建立课程任务库和智能体库，并对学生身份和任务身份进行匿名处理。在此基础上，系统为每名学生分配 10 道匿名任务，生成并发放匿名任务包。第二阶段结束后，助教端继续接收学生提交，统一整理任务第二版、智能体第二版和评审意见，并在统一运行环境和统一资源限制下完成后台评测，最终汇总任务难度、智能体表现、常见失败情况，以及学生从第一版到第二版的修改结果。



课程主要分为两个正式阶段，中间安排一次匿名任务测试。

第一阶段，学生提交任务第一版和智能体第一版。

中间阶段，每名学生获得 10 道匿名任务，并使用自己的智能体第一版运行这些任务。系统记录每道任务的运行结果和诊断信息。

第二阶段，学生根据这些真实运行结果填写评审意见，并完成任务第二版和智能体第二版。

学生完成第二阶段后，教师端统一进行最终验证和后台评测。

## 第一阶段

第一阶段学生主要完成：

```text
任务第一版
+
数据文件
+
标准答案程序
+
智能体第一版
```

学生在本地完成运行测试后，使用课程命令生成提交包，并对最终提交包进行验证。

```bash
bin/datac submission build   --input /workspace   --student-id <student-id>   --phase P1
```

然后执行：

```bash
bin/datac submission validate   --input /workspace/submission/BigData_P1_<student-id>.zip   --phase P1
```

学生本地验证和助教收包后的验证使用同一套课程规则。学生在本地看到的验证结果，就是助教收到同一个提交包以后会重新检查的内容。

最终提交文件为：

```text
BigData_P1_<student-id>.zip
```



## 匿名任务测试

第一阶段收齐后，助教端统一整理任务，并为每名学生分配 10 道匿名任务。

学生收到匿名任务包后执行：

```bash
bin/datac exposure import   --package /workspace/BigData_Exposure_<reviewer-id>.tar.gz   --workspace /workspace
```

然后使用自己的智能体第一版运行：

```bash
bin/datac exposure run   --workspace /workspace
```

学生通过这些结果判断自己的智能体在哪些任务上能够正常工作，在哪些任务上会失败，以及失败发生在问题理解、数据读取、筛选、关联、统计、时间处理、结果检查或资源使用等哪个环节。

## 第二阶段

第二阶段学生需要完成三类成果：

```text
1. 任务第二版
2. 智能体第二版
3. 10 份评审意见
```

学生先根据 10 道匿名任务的运行结果填写评审意见，再修改自己的任务和智能体。

任务第二版主要反映学生对问题定义、数据设计、统计口径、边界情况和标准答案可靠性的进一步修改。

智能体第二版主要反映学生根据真实失败结果，对问题理解、执行步骤、结果检查、错误恢复和资源使用等方面做出的改进。

完成后，学生生成第二阶段提交包：

```bash
bin/datac submission build   --input /workspace   --student-id <student-id>   --phase P2
```

并在正式提交前再次验证：

```bash
bin/datac submission validate   --input /workspace/submission/BigData_P2_<student-id>.zip   --phase P2
```

最终提交文件为：

```text
BigData_P2_<student-id>.zip
```
